# Промпты генерации страниц — комплект под аутсорс

Здесь всё, что нужно стороннему исполнителю (человеку или другой модели), чтобы писать
страницы для нашего SFT-набора. Комплект самодостаточен: кроме файлов этой папки и
входного `briefs.jsonl` ничего знать не требуется.

| файл | что это |
|---|---|
| `01_page_generation.md` | **Основной промпт.** Процедура и все жёсткие требования. Отдаётся исполнителю целиком, дословно. |
| `02_batch_task.md` | Шаблон задания на одну пачку. Подставить id и путь к пачке. |
| `03_brief_format.md` | Формат входного ТЗ: что означает каждое поле. |
| `04_sft_prompts.md` | Промпты, с которыми обученная модель будет работать на инференсе. Справочно — чтобы исполнитель понимал, во что превратится его страница. |

## Как это устроено

Схема обратная привычной («reverse construction», UI2Code^N 2511.08195 §3.2.2): сначала
пишется идеальный HTML, потом из него рендерится скриншот, и уже скриншот становится
запросом к обучаемой модели. Поэтому качество страницы — это буквально качество разметки,
которую модель выучит наизусть.

Ошибка исполнителя не «портит один пример», а закрепляется как правило. Именно поэтому в
`01_page_generation.md` так много жёстких «нельзя»: каждое из них — реальный дефект,
пойманный на пилоте.

## Порядок работы

1. Исполнитель получает `01_page_generation.md` и пачку ТЗ (jsonl, 4–12 строк).
2. На каждое ТЗ пишет один файл `<id>.html`.
3. Прогоняет валидатор **один раз на всю пачку** и переписывает отвергнутое.

Валидатор:

```bash
VENDOR_DIR=$(pwd)/Data/vendor .venv/bin/python Data/converters/synth/build.py --only <id1> <id2> ...
```

Он не косметический: рендерит страницу настоящим браузером и ловит то, чего не видно в
коде — пустой экран из-за упавшего React, высоту сверх пиксельного бюджета, схлопнувшуюся
вёрстку, слишком разреженную или слишком плотную страницу для своего тира.

## Чего валидатор НЕ ловит

Проверку глазами он не заменяет. На пилоте страница со стрелкой карусели, легшей поверх
абзаца, прошла все пороги: линт чист, узлов сколько надо, скриншот не пустой — а текст
под стрелкой нечитаем. Такие дефекты находятся только просмотром PNG:

```bash
.venv/bin/python Data/converters/synth/contact_sheet.py pages
```

## Если отдаёте это другой модели

Три места, где чаще всего ошибаются, и их стоит проговорить отдельно:

1. **Плейсхолдер картинки в JSX** — только через `dangerouslySetInnerHTML`. Вставленный
   дословно, он роняет React и обнуляет страницу (раздел про плейсхолдеры в промпте).
2. **Потолок высоты 2048 px.** Плотность набирается колонками и компактными строками,
   а не длиной страницы. Это самое частое нарушение на тире L.
3. **Поле `visual` важнее, чем кажется.** Без него исполнитель по инерции рисует один и
   тот же светлый SaaS-интерфейс, и весь набор теряет визуальное разнообразие.
