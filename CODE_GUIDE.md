# Разбор кодовой базы Screenshot2Code

Для того, кто открывает репозиторий впервые и хочет понять не «где какие файлы»
(это в [`docs/STRUCTURE.md`](docs/STRUCTURE.md)), а **как всё работает и почему
сделано именно так**. Составлено 13 августа 2026 по ветке `data`.

Порядок чтения: задача → пайплайн → контракт → четыре трека → окружение →
грабли → что сломано прямо сейчас.

---

## 1. Задача

По скриншоту веб-страницы получить HTML, который её воспроизводит. База —
Qwen3.5-4B (VLM). Метрика — Design2Code. Ориентир метода — статья UI2Code^N
(`Data/papers/UI2CodeN_2511.08195.pdf`): три стадии, pretrain → SFT → RL.

Три типа задач, они же значения поля `task_type` в датасете:

| `task_type` | вход | выход |
|---|---|---|
| `drafting` | скриншот | HTML с нуля |
| `polishing` | эталонный скриншот + текущий рендер + текущий HTML | исправленный HTML |
| `editing` | скриншот + HTML + инструкция на естественном языке | изменённый HTML |

Сегодня реально обучено и померено только `drafting`. `polishing` и `editing`
собираются синтетическим конвейером, но прогонов на них ещё не было.

**Ключевое, что легко упустить:** обучение и бенч живут в **разных образах**, и
общий диск примонтирован в них **по разным путям**. Путь `/storage/...`,
переданный в бенч, внутри него не существует.

## 3. Контракт данных — единственный интерфейс между треками

`SFT/DATA_FORMAT_CONTRACT.md`. Датасет сохраняется через `save_to_disk`,
читается через `load_from_disk`. Колонки:

| колонка | тип | обязательна | смысл |
|---|---|---|---|
| `images` | `Sequence(Image())` | да | список PIL-картинок. Для `polishing` **первым идёт эталон**, вторым — текущий рендер. Перепутать = учить наоборот |
| `target_html` | string | да | что модель должна выдать |
| `task_type` | string | да | `drafting` / `polishing` / `editing`; проверяется в `SFT/data/loader.py` |
| `current_html` | string | для polishing/editing | исходный код, который правим |
| `instruction` | string | для editing | что именно изменить |
| `impl` | string | нет | `static_inline` или `react_cdn` — **выбирает промпт** |

`impl` появился вместе с синтетикой. Его отсутствие трактуется как
`static_inline`, поэтому старые наборы не ломаются. Смысл: в наборе смешаны два
стиля вывода, и без разделяющей инструкции один скриншот отображался бы в два
разных валидных таргета — противоречивый супервижн.

## 4. Четыре трека

### `Data/` — сборка датасетов

Конвертеры названы **по источнику**, а не по задаче: `drafting`/`polishing`/
`editing` — это поле в контракте, а не папка.

Ядро всей логики — `converters/websight/convert_lib.py`. `webcode2m/convert_lib.py`
не копирует его, а подгружает через `importlib` и переопределяет только своё.

Синтетика (`generators/synth/` → `converters/synth/`) идёт по схеме обратной
привычной: сначала пишется идеальный HTML, потом из него рендерится скриншот, и
уже скриншот становится запросом к модели. Поэтому качество страницы — это
буквально качество разметки, которую модель выучит наизусть, и приёмка в
`build.py` жёсткая: линт, рендер, отбраковка по числу DOM-узлов, по пустоте
скриншота, по бюджету токенов, по near-dup.

`slop.py` — детектор машинных дефолтов (одинаковые градиенты, кикеры, выдуманные
числа). Это **отчёт, а не отбраковка**: slop измеряет разнообразие набора,
решение принимает человек.

### `SFT/` — обучение

Владелец трека — не Data. Точка входа `train/train_sft.py`, запускается только
через `SFT/run.sh` (он поднимает контейнер и пробрасывает креды).

Три неочевидные вещи:
- **Маскирование лосса по ходам ассистента** (`train/formatting.py`,
  `make_collate_fn`): лосс считается только по ответу модели, промпт и картинка
  маскируются `-100`.
- **Бакетинг по бюджету токенов** (`train/batching.py`): батчи переменного
  размера под общий потолок токенов, а не фиксированный `batch_size`.
- **Отбраковка по длине до загрузки модели** (`data/filtering.py`): считает
  длину каждого сэмпла с учётом визуальных токенов и выкидывает не влезающие,
  печатая отчёт. Один слишком длинный сэмпл иначе роняет ран по OOM.

### `Evaluation/` — четыре разных инструмента

С 8 августа каталог разделён, и это важно понимать:

| подкаталог | что |
|---|---|
| `metrics_only/` | **основной бенч**, им сняты все числа в `RESULTS.md` |
| `judge_one_gpu/` | те же метрики + VLM-судья (попарное сравнение с базой) |
| `judge_prompt/` | калибровка промпта судьи |
| `streamlit/` | веб-просмотр генераций |

У каждого свой Dockerfile, свой `run.sh`, свой образ. **`render.py` и `metrics.py`
существуют в нескольких копиях, и они разошлись** — подробности в §7.

Внутри `metrics_only/` стоит знать:
- `final_score` — **геометрическое** среднее пяти метрик, сознательное отличие
  от оригинала Design2Code. Арифметическое лежит рядом как `final_score_arithmetic`.
  Разница принципиальна: у сломанных моделей `clip` держится ~0.79 даже когда
  всё остальное ноль, и арифметическое рисует 0.158 там, где геометрическое
  честно даёт 0.000.
- Среднее считается **взвешенно** через `MetricAccumulator`, а не как среднее
  средних батчей — иначе неполный последний батч получил бы тот же вес, что полный.
- `progress.json` даёт **resume**: перезапуск той же командой продолжает с
  первого несчитанного батча.
- Упавшие сэмплы **исключаются** из среднего, а не считаются нулём. Это главная
  ловушка при чтении чисел, см. §7.

### `RL/` — GRPO на WebCode2M

Отдельный трек на verl, reward по рендеру. Диагностический: текущий
pixel-similarity reward завышает оценку из-за больших совпадающих областей фона.
`ROADMAP.md` отмечает, что статья UI2Code^N именно такой reward отвергла.

## 5. Оркестрация прогонов

`experiments/*.sh` — на хосте, не в контейнере. Они сами поднимают контейнеры
через `SFT/run.sh` и `Evaluation/metrics_only/run.sh`.

Общий код — `experiments/lib/common.sh`: `say`, `phase`, `mkchmod`,
`count_samples`, переменная `STORAGE`. Подключается сразу после перехода в
корень репозитория.

**Планировщик очереди** `experiments/queue/runner.sh` — по экземпляру на машину,
координация через каталог на общем диске (не по ssh: агент ключей форвардится
только пока жив ssh-сеанс). Захват задания — атомарный `mkdir`.

⚠ Признак занятой карты — **наличие процесса на ней**, а не объём занятой
памяти. RL-трек с офлоадом между фазами показывает в `nvidia-smi` почти ноль при
живом прогоне; заехать в этот промежуток — значит убить чужое обучение.

⚠ Упавшее задание **остаётся в `claims/`** и автоматически не перезапускается.
Чтобы возобновить, claim надо снять руками. Сейчас там висят четыре таких.

## 6. Окружение

| | образ `sft` | образ `design2code-bench` |
|---|---|---|
| общий диск внутри | `/storage` | `/mnt/storage-1` (read-only) |
| HF-кэш | `$HF_HOME` | `/root/.cache/huggingface` |
| python | `/opt/venv/bin/python` (не `python3`) | entrypoint = сам бенч |

Локально (ноутбук) — `.venv` в корне и `requirements-local.txt`: только анализ и
ноутбуки, ни обучения, ни бенча.

**Образы собираются на каждой машине отдельно** и могут различаться между
a100-2 и a100-3. После правки любого `.py` в `Evaluation/` образ надо пересобрать.

Грабли окружения, каждая стоила времени:
- `GPUS='"device=1,2"'` — **внутренние кавычки обязательны**, без них docker падает rc=125.
- `--tensor-parallel-size` должен делить 32 головы внимания → 1, 2 или 4, **не 3**.
- UID `v.kozlov` различается на машинах (1037 и 1004): файлы, созданные на одной,
  на другой недоступны на запись, и редирект в существующий лог падает молча.
- Файлы, созданные docker'ом, принадлежат root — удалять их надо из контейнера.
- `TMPDIR` Chromium'а на сетевой диск ставить нельзя — падает `Target crashed`.
- `/mnt/storage-1/Screenshot2Code` и `/mnt/storage-1/ScreenShot2Code` — **оба наши**,
  но это разные каталоги. Путь копировать, а не набирать по памяти.

## 7. Что нужно знать, прежде чем верить любому числу

Это самая важная часть гайда. У проекта богатая история измерений, которые
оказались неверными.

**1. Режим декодирования.** До 6 августа бенч не задавал `SamplingParams` и
работал на дефолтах vLLM — сэмплинг T=1.0 без seed. Все числа, снятые раньше, с
новыми **несравнимы**. Сейчас по умолчанию greedy.

**2. Штраф за повторы решает больше, чем всё обучение.** База под greedy без
штрафа даёт 0.656, со штрафом 1.05 — **0.801**, что выше любого нашего
дообученного чекпоинта. Свип штрафа оборван на растущей кривой. Пока он не
досчитан, вывод «дообучение хуже базы» неотделим от «мы не откалибровали
декодирование». Разбор — [E12](docs/experiments/2026-08-07-wc2m-15k-ab.md).

**3. Знаменатель `final_score` плавает.** Упавшие сэмплы исключаются из
среднего. В E12 у базы оценено 484/484, у дообученных 430–479. В прогонах
WebSight70k у 9B из среднего выпало **46%** набора. Чем чаще модель падает, тем
выше её остаточный скор. **Всегда смотреть `n_scored`, а не только скор.**

**4. Харнесс уже четырежды обнулял результаты.** UI2Code^N полтора дня числилась
как 0.000 при реальных 0.874. Причины: `html.parser` резал документ на первом
JSX-теге; сырой вывод модели не сохранялся; метрика разбирала статический DOM у
React-страниц; синхронный Playwright внутри asyncio. Всё починено — **но только
в `metrics_only/`**. В `judge_one_gpu/` и `streamlit/` этих фиксов нет.

**5. Ноль в таблице — не обязательно про модель.** Сначала смотреть байт на
токен и `pred_raw.html`, потом делать выводы.

**6. `eval_loss` не предсказывает скор.** У E4 лучший лосс из всех и худший
`final_score`. Отбирать чекпоинты по лоссу нельзя.

**7. Метрика мягче человеческой оценки.** Глазом сходство 0.5–0.6 там, где
метрика даёт 0.8: она поощряет аккуратные упрощённые версии.

Полный реестр несостыковок — [`docs/experiments/DIVERGENCES.md`](docs/experiments/DIVERGENCES.md).

## 8. Известные проблемы кода на сегодня

| что | где | статус |
|---|---|---|
| `--shuffle-buffer-size` ничего не делает; бенч берёт **префикс** сплита, а не случайную выборку | `metrics_only/run_benchmark_batched.py` | задокументировано, **не чинить** — сменит выборку и обесценит прошлые числа |
| `MAX_PIXELS` в конвертерах 1.31 Мп, в обучении и бенче 2.10 Мп | `Data/converters/websight/convert_lib.py` | не трогать не глядя: влияет на состав уже собранных наборов |
| `MAX_PIXELS` продублирован литералом в десятке мест | `experiments/*.sh`, `Evaluation/` | свести к одному источнику |
| режим декодирования не логируется в ClearML | `metrics_only/tracking.py` | различим только по тегам |
| четыре фикса харнесса только в `metrics_only/` | `judge_one_gpu/`, `streamlit/` | переносить — к владельцам eval-трека |
| `datasets` 5.0.0 локально против `<5` в обучении | `requirements-local.txt` / `SFT/pyproject.toml` | формат `save_to_disk` между мажорами менялся |

## 9. Как запустить

```bash
# собрать датасет из WebSight (через docker, из корня репо)
docker build -t ws-conv -f Data/converters/websight/Dockerfile .
docker run --rm -v "$PWD":/work --shm-size=2g ws-conv --target 5000 --n-workers 32
.venv/bin/python Data/converters/make_split.py Data/websight_drafting_pilot <OUT> --val-frac 0.05

# обучение (на машине с картами)
./experiments/run_wc2m_ab.sh          # или другой оркестратор из experiments/

# один бенч
cd Evaluation/metrics_only && ./build.sh
HOST_OUTDIR=/путь ./run.sh --model Qwen/Qwen3.5-4B --n-samples 484 --batch-size 484 \
  --max-new-tokens 16384 --max-pixels 2097152 --repetition-penalty 1.05
```

Перед первым запуском прочитать [`Evaluation/metrics_only/RUNNING.md`](Evaluation/metrics_only/RUNNING.md)
— там про то, почему нельзя передавать `--outdir` и почему имя контейнера персональное.

**Числа любого прогона переносить в [`docs/RESULTS.md`](docs/RESULTS.md).**
Прогон, оставшийся только в `summary.json` на диске, теряется — так уже
случилось с A/B на 15k и с прогонами WebSight70k.
