# ScreenShot2Code — демо (Streamlit)

Загружаешь скриншот веб-страницы → дообученный Qwen3.5-4B генерирует
HTML/Tailwind код → код рендерится обратно в картинку (тот же движок,
что в основном пайплайне метрик, `render.py`) → показывается side-by-side
с оригиналом.

Инференс — напрямую через `transformers` (без vLLM): для одного запроса
за раз батчевый сервер vLLM не даёт выгоды и только усложняет запуск.

## Почему всё крутится на сервере, а не локально

GPU есть только на сервере, локально её нет. Поэтому **всё приложение
целиком** (Streamlit + модель + Playwright для рендера) запускается прямо
на GPU-сервере. Со своего компьютера ты не открываешь никакой сетевой порт
сервера наружу — вместо этого пробрасываешь его к себе по SSH-туннелю:

```
[твой браузер] --http--> [localhost:8501 у тебя] --ssh tunnel--> [localhost:8501 на сервере] --> [Streamlit + модель + GPU]
```

Никакого дополнительного API писать не нужно — сам Streamlit уже слушает
TCP-порт, туннель просто прокидывает его к тебе как будто он локальный.

## Вариант Docker (рекомендуется)

Файлы: `Dockerfile`, `entrypoint.sh`, `build.sh`, `run.sh` — тот же паттерн,
что в основном бенчмарк-пайплайне (`build.sh`/`run.sh` там же).

### 1. Собрать образ (на сервере)

```bash
./build.sh
# или свой тег:
./build.sh screenshot2code-demo:v1
```

### 2. Запустить, выбрав ОДНУ GPU из нескольких

```bash
GPUS='"device=2"' ./run.sh \
    --model /mnt/storage-1/ScreenShot2Code/model_weights/train_res_s42_20260729-185222/ \
    --device cuda
```

`GPUS='"device=N"'` — тот же формат, что в `run.sh` основного пайплайна
(`GPUS='"device=2"' ./run.sh ...`), N — номер карты по `nvidia-smi` (0..3).
Внутри контейнера видна только эта одна карта, поэтому `--device cuda`
(без номера) — это то же самое, что `cuda:0`, менять не нужно.

Без `--model` возьмётся `Qwen/Qwen3.5-4B` с HF hub — удобно для проверки,
что контейнер вообще стартует, до подключения своего чекпоинта.

По умолчанию `run.sh`:
- монтирует `~/.cache/huggingface` (хост) → `/root/.cache/huggingface` —
  модель скачивается один раз и переиспользуется между перезапусками
  контейнера;
- монтирует `/mnt/storage-1` (хост, read-only) → `/mnt/storage-1`
  (контейнер) — тот же общий диск с чекпоинтами, что в основном пайплайне;
  если на хосте он смонтирован не туда, задай `HOST_STORAGE=<путь>`;
- пробрасывает порт `8501` (хоста) → `8501` (контейнера); поменять —
  `PORT=8502 ./run.sh ...`;
- задаёт `--shm-size 1g` и `--ipc=host` — без этого Chromium может падать
  при рендере (тот же нюанс, что в основном пайплайне).

### 3. Проброс порта и открытие (на своём компьютере)

```bash
ssh -N -L 8501:localhost:8501 user@gpu-server
```
Затем открой `http://localhost:8501` в браузере. Если менял `PORT` — подставь
его и в `-L`, и в адрес браузера.

### 4. Пересоздать после изменения кода

```bash
./build.sh && GPUS='"device=2"' ./run.sh --model ...
```
`run.sh` сам удаляет старый контейнер с тем же именем перед пересозданием
(данные в volume — HF-кэш, `/mnt/storage-1` — не трогаются).

### 5. Проверить, что контейнер видит нужную (и только нужную) GPU

```bash
docker exec screenshot2code-demo nvidia-smi
```
Должна быть видна одна карта — та, что указана в `GPUS`.

## Вариант без Docker (venv)

## 1. Установка (на сервере)

```bash
cd /path/to/ScreenShot2Code/demo   # эта папка
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
playwright install --with-deps chromium   # тот же Chromium, что в основном пайплайне
```

Если venv для основного бенчмарк-пайплайна уже существует и там уже стоит
подходящий `transformers`/`torch`/`playwright` — можно переиспользовать его
вместо нового окружения, тогда просто:
```bash
pip install streamlit
```

## 2. Запуск (на сервере)

```bash
streamlit run app.py --server.port 8501 --server.address 0.0.0.0 -- \
    --model /mnt/storage-1/ScreenShot2Code/model_weights/train_res_s42_20260729-185222/ \
    --device cuda
```

Всё, что идёт **после `--`** (двойное тире) — аргументы самого `app.py`,
а не Streamlit. `--server.address 0.0.0.0` нужен, чтобы порт вообще был
слушаем изнутри контейнера/сервера (сам туннель ниже всё равно ограничивает
доступ только тебе — наружу этот порт с сервера не выставляется).

Если сервер за пределами локальной сети НЕ должен слушать `0.0.0.0` по
соображениям безопасности — используй `--server.address 127.0.0.1` и
пробрасывай именно `127.0.0.1:8501` в туннеле (см. ниже), тогда порт не
будет доступен вообще никому, кроме как через SSH.

Параметры `app.py`:
- `--model` — путь к чекпоинту (HF hub ID или локальный путь на
  `/mnt/storage-1/...`, как в `run.sh` основного пайплайна).
- `--max-new-tokens` — лимит генерации (по умолчанию 4096, дальше можно
  подвинуть слайдером прямо в UI).
- `--device` — `cuda`, `cuda:0` для конкретной карты, или `cpu`.

Если сервер многопользовательский и GPU нужно выбрать явно, для одной
конкретной карты (аналог `GPUS='"device=2"'` в основном пайплайне):
```bash
CUDA_VISIBLE_DEVICES=2 streamlit run app.py -- --model ... --device cuda
```

## 3. Проброс порта и открытие (на своём компьютере)

```bash
ssh -N -L 8501:localhost:8501 user@gpu-server
```
(`-N` — не открывать шелл, только держать туннель; можно в отдельном
терминале/tmux, либо убрать `-N` и работать в этой же SSH-сессии).

Затем открой в браузере:
```
http://localhost:8501
```

## Заметки

- Модель грузится **один раз** при старте Streamlit-процесса
  (`@st.cache_resource`) — повторные генерации в UI не перезагружают веса.
- Промпт — 1-в-1 скопирован из `run_benchmark_batched.py` (`PROMPT` и
  `extract_html`), чтобы демо честно отражало то же поведение модели, что
  и в бенчмарке.
- Рендер использует `prepare_and_render` из `render.py` — то есть `<img>`
  теги в выходе модели так же заменяются на серые плейсхолдеры, как в
  основном пайплайне подсчёта метрик.
- Промежуточные HTML/PNG каждого запроса сохраняются в
  `demo/streamlit_runs/<timestamp>/` — можно почистить вручную, автоочистки
  нет.
- Если `AutoModelForImageTextToText`/`AutoProcessor` не подхватывают архитектуру
  Qwen3.5 из установленной версии `transformers` — обнови её
  (`pip install -U git+https://github.com/huggingface/transformers.git`),
  как это уже сделано в `Dockerfile` основного пайплайна.
