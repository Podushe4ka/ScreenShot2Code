# UI2Code^N нашим харнессом: 0.000 → 0.874 (6 августа 2026)

**Статус:** на 40 сэмплах завершён. Полный Design2Code (484) — идёт.

## Вопрос

UI2Code^N (`zai-org/UI2Code_N`, GLM-4.1V-9B, заявлена как SOTA на Design2Code) —
кандидат в учителя для дистилляции. Прежде чем строить на ней пайплайн, надо
измерить её **нашими** метриками, а не верить числу из статьи.

## Результат

40 коротких Design2Code (`d2c_short_bench`), greedy, `--materialize-dom`:

| модель | final | block | text | position | color | clip | нулей |
|---|---:|---:|---:|---:|---:|---:|---:|
| **UI2Code^N** (родной промпт) | **0.874** | 0.902 | 0.933 | 0.835 | 0.866 | 0.884 | 2/40 |
| база Qwen3.5-4B | 0.758 | 0.793 | 0.809 | — | — | 0.879 | — |

Учитель уверенно выше базы. Первый замер того же прогона давал **0.000** — вся
разница оказалась дефектами харнесса, не модели.

### Два оставшихся нуля — ошибки самой модели

Проверено по консоли браузера на её сыром выводе:

| сэмпл | ошибка | суть |
|---|---|---|
| 3 | `username is not defined` | JSX ссылается на необъявленную переменную, React сносит дерево |
| 20 | `Unexpected token, expected "}" (123:37)` | синтаксическая ошибка, Babel не компилирует |

Такая страница не отрисуется ни в одном браузере — ноль заслуженный.

## Четыре дефекта харнесса, каждый обнулял результат

Отправная точка: `finish_reason: stop` у всех 40 при 740–3488 токенах и бюджете
16384 — генерация завершалась штатно, значит виноват конвейер.

### 1. `html.parser` уничтожал JSX

`replace_images_with_placeholder` делала round-trip
`BeautifulSoup(html_text, "html.parser")` → `str(soup)`. На странице со
`<script type="text/babel">` парсер выходил из режима сырого текста на первом
JSX-теге и выбрасывал остаток документа, дописав `</script></body></html>`.

Мера потери: **0.34–1.7 байта на сгенерированный токен при норме 3.5–4.2** у
27 сэмплов из 40 — и это ровно те 27, что давали ноль.

Починка: в образ добавлен `html5lib`, парсер переключён на него (с откатом на
`html.parser`). После — `clean_len ≈ raw_len` у всех 40.

### 2. Сырой вывод модели не сохранялся

На диск писался только результат обработки, поэтому дефект №1 был невидим:
«модель выдала мусор» неотличимо от «мы его испортили». Теперь рядом с
`pred.html` пишется `pred_raw.html`, а в `results.csv` — `raw_len`/`clean_len`.

### 3. Метрика читает статический DOM

`metrics.py` разбирает исходник: `_process_html` перекрашивает текстовые теги в
тексте файла, `extract_text_recursive` обходит `soup.body`. У React-страницы в
`<body>` только `<div id="root">` — статических блоков нет, поэтому
block/text/position/color нулевые **по построению**, а `clip` (работает с
картинками) даёт 0.742.

Починка: флаг `--materialize-dom` (**по умолчанию выключен**, чтобы прежние числа
остались сравнимыми). Страница открывается, JS отрабатывает, снимается итоговый
DOM. Два обязательных условия, оба выяснены экспериментально:
- отдавать по **HTTP**, не через `file://` — Babel не трансформирует инлайновый
  `<script type="text/babel">` с file-схемы и сам пишет об этом в консоль;
- после снятия DOM **вырезать скрипты** — иначе при следующем открытии страницы
  React заново отрисует `#root` и сотрёт перекраску, которой ищутся блоки.

### 4. Синхронный Playwright внутри asyncio-цикла

Первая версия материализации использовала `sync_playwright()`, а в воркере уже
крутится фоновый asyncio-loop для `render_many`. Результат —
`Playwright Sync API inside the asyncio loop` у **32 сэмплов из 40**; проходили
только первые, успевшие до старта цикла. Переписано на async с переиспользованием
общего браузера через `_run_coro`.

### Плюс: CDN резал запросы

40 страниц × 5 библиотек = ~200 запросов подряд с одного адреса, часть не
загружалась, React не стартовал. React, ReactDOM, Babel, Tailwind и Font Awesome
скачаны в `/mnt/storage-1/Screenshot2Code/vendor/` и подменяются локально через
перехват запросов — внешняя сеть при материализации больше не нужна.

## Как запускать

Модель — GLM-4.1V, у неё свои требования:

| параметр | значение | почему |
|---|---|---|
| `--prompt-file` | `Please generate the corresponding html code for the given UI screenshot.` | родная формулировка модели; мерить чужим промптом — мерить рассогласование |
| `--min-pixels 0 --max-pixels 0` | не передавать | это параметры Qwen2VL-процессора; у `Glm4vImageProcessor` бюджет задаётся через `size`, чужие kwargs роняют загрузку |
| `--gpu-memory-utilization` | **0.70** | коридор узкий: при 0.9 не поднимается `clip_server`, при 0.6 самому vLLM не хватает на KV-кэш |
| `--materialize-dom` | вкл | модель пишет React |
| пауза между прогонами | 60 с | иначе следующий запуск видит меньше свободной VRAM, чем есть |

Скрипт: `experiments/bench_ui2code.sh`. ClearML включён (задача
`8e2a213bc17d4e7caa048766c9b47d1a` для прогона с нашим промптом).

## Что это значит для проекта

1. **Учитель годится.** 0.874 против 0.758 у базы — запас есть, дистилляция
   осмысленна.
2. ⚠ **Но таргеты учителя — React с CDN.** Обучать студента на них напрямую
   нельзя: он выучит тот же формат, и мы упрёмся ровно в ту же стену (метрика
   не видит статических блоков). Для дистилляции таргеты надо **материализовать**
   — инструмент теперь есть и это тот же `materialize_dom`.
3. **Дефект №1 стоит проверить на своих прогонах.** Qwen выдаёт статический HTML
   без `<script>`, так что скорее всего не задел, но подтвердить дёшево:
   посчитать байт/токен по сохранённым примерам свипов.
