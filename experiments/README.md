# Оркестраторы прогонов

Скрипты запускаются **на хосте**, а не внутри контейнера: они сами поднимают
контейнеры через `SFT/run.sh` и `Evaluation/run.sh`. Изнутри контейнера docker
недоступен, работать не будут.

Все пишут в `/mnt/storage-1/Screenshot2Code`. Запускать под `setsid nohup` или
в `tmux` — прогоны идут часами и не должны умирать вместе с ssh-сессией:

```bash
setsid nohup ./experiments/sweep_soft.sh < /dev/null > /mnt/storage-1/Screenshot2Code/run.out 2>&1 &
```

### Прогоны целиком (обучение + бенч)

| скрипт | что делает | статус |
|---|---|---|
| `run_pilot.sh` | пилот на WebCode2M: E1–E6, обучение → merge LoRA → бенч, всё в ClearML | отработал |
| `run_night.sh` | ночная цепочка: бенч 1k → генерация 3k → экспы на 3k → бенч → сводка | отработал |
| `run_wc2m_15k.sh` | прогон на WebCode2M 15k: сборка набора, обучение под 4 карты, бенч | отработал |
| `run_wc2m_ab.sh` | A/B на 15k: **чистый** набор против **сырого**, один рецепт E3 на обеих ветках | отработал, [E12](../docs/experiments/2026-08-07-wc2m-15k-ab.md) |
| `sanity_d2c.sh` | sanity-overfit на Design2Code как есть | **устарел**: таргеты не влезали в `max_length` и резались |
| `sanity_fit.sh` | sanity-overfit на коротких Design2Code, `train == eval`. Собирает `data/d2c_short` и `hf_cache/d2c_short_bench` | рабочий |
| `sanity_sweep.sh` | свип по эпохам: 5 эпох, чекпоинт каждую, бенч каждого | рабочий |
| `sweep_soft.sh` | мягкий рецепт (lr 5e-6, cosine, warmup 0.1) + greedy-бенч каждой эпохи | рабочий |

### Только бенч (без обучения)

| скрипт | что делает | статус |
|---|---|---|
| `bench_all.sh` | добенчить готовые чекпоинты пилота; умеет ждать конца обучения (`NOWAIT=1` — не ждать, `ONLY="E1 E5"` — часть) | рабочий |
| `sweep_greedy.sh` | перебенч ГОТОВЫХ чекпоинтов в greedy, без переобучения | рабочий |

| `bench_queue.sh` | очередь одиночных бенчей на ОДНОЙ карте, модель за моделью. Все прогоны одним образом и одними параметрами — иначе замеры снова несравнимы | рабочий |
| `bench_clean_when_ready.sh` | дождаться конца обучения чистой ветки A/B и запустить её бенч | разовый |

### Планировщик очереди

`queue/runner.sh` — по одному экземпляру на КАЖДОЙ машине. Сам находит свободные
карты и берёт работу из `queue/jobs/*.job`. Координация между машинами — через
каталог на общем диске (`Q=/mnt/storage-1/Screenshot2Code/queue`), а не по ssh:
агент ключей форвардится только пока жив ssh-сеанс, и оркестратор, ходящий с
машины на машину, умрёт вместе с закрытым ноутбуком.

```bash
HOST_TAG=a100-3 ./experiments/queue/runner.sh
```

Задание — обычный bash-скрипт, объявляющий требования строками-заголовками
(`# NEED_GPUS=2`, `# FREE_MB=5000`). Раннер экспортирует в него `GPU_IDS` и
`GPU_COUNT`. Захват задания — атомарный `mkdir` в `claims/`: он атомарен даже на
сетевой ФС, в отличие от «проверить файл, потом создать».

⚠ **Признак занятой карты — наличие процесса на ней, а не объём занятой памяти.**
RL-трек (verl/GRPO) идёт с `param_offload`+`optimizer_offload`+`free_cache_engine`:
между фазами он выгружает параметры в RAM и освобождает KV-кэш, и `nvidia-smi`
показывает почти ноль при живом прогоне. Занять карту в этот промежуток — значит
убить чужое обучение, когда оно попросит память назад. Двенадцать часов чужого
прогона так уже потеряны.

Что стоит в очереди сейчас — `queue/jobs/`; что из этого посчитано, а что нет —
в [E12](../docs/experiments/2026-08-07-wc2m-15k-ab.md), раздел «Что осталось
невыполненным».

### Прочее

`hold_gpus.py` — держать карты занятыми, чтобы их не увёл сосед, пока готовишь
прогон. Запускается руками, ни из одного скрипта не вызывается.

Описания самих экспериментов и их результаты — в [`docs/experiments/`](../docs/experiments).

## Переменные окружения

| переменная | смысл |
|---|---|
| `STORAGE` | где на хосте примонтирован общий диск. По умолчанию `/mnt/storage-1`; рабочий каталог берётся как `$STORAGE/Screenshot2Code` |
| `GPUS` | какие карты пробросить, **строго** `GPUS='"device=1,2"'` — внутренние кавычки обязательны |
| `BENCH_GPUS` | то же для бенча, если он должен идти на другой карте (`sweep_soft.sh`) |
| `NPROC` | число процессов torchrun = число карт для обучения |
| `TP` | `--tensor-parallel-size` бенча; должен делить 32 головы → 1, 2 или 4, **не 3** |
| `LR`, `EPOCHS` | гиперпараметры, где скрипт их поддерживает |

## Грабли, стоившие времени

- **Чекпоинты лежат глубже, чем кажется.** Трейнер кладёт их в
  `$OUT/<run_name>/checkpoint-N`, а не в `$OUT/checkpoint-N`. Глоб только по
  верхнему уровню молча ничего не находит, и скрипт «успешно» завершается,
  ничего не сделав.
- **Скрипт обязан лежать в репозитории.** Все они делают
  `cd "$(dirname "$0")/.."; REPO="$PWD"`. Копия, запущенная из произвольного
  каталога, не найдёт `Evaluation/run.sh`.
- **Путь к датасету зависит от образа.** `sft` видит диск как `/storage`,
  бенч — как `/mnt/storage-1`, а HF-кэш как `/root/.cache/huggingface`.
- **Разный UID на машинах** ломает дозапись в чужие логи — см.
  [`docs/STRUCTURE.md`](../docs/STRUCTURE.md).
- **В одном `local` нельзя ссылаться на соседнюю переменную:** bash раскрывает
  все аргументы до присваивания, и под `set -u` это `unbound variable`.
